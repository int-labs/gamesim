# 🎨 IntLabs Pixel Simulation — Master Style Notes v01

This document defines the **visual system rules** for the IntLabs Pixel Simulation.

This is the **single source of truth** for all asset creation.

---

# 🧠 1. Core Philosophy

Our simulation is NOT just a game.

It is:
- a **decision-making tool**
- a **learning system**
- a **visual feedback engine**

Based on IntLabs methodology:
- Participants learn by **doing → feedback → iteration** :contentReference[oaicite:0]{index=0}
- Simulations must feel **real, engaging, and insightful**

👉 Therefore:
Every visual must:
- represent a decision
- communicate an outcome
- support learning

---

# 🎯 2. Design Principles

### 1. Clarity over decoration
Users must understand instantly.

### 2. Consistency over creativity
Style must NOT drift between assets.

### 3. Meaningful detail
Every pixel must have purpose.

### 4. Feedback-driven visuals
States must clearly show system response.

### 5. System-first thinking
Assets are part of a system, not standalone art.

---

# 🧱 3. Pixel Rules

### Canvas
- Base grid: **1x pixel grid (no anti-aliasing)**
- Standard size: **32x32 / 48x48 / 64x64**

### Outline
- Outer outline: **1px dark**
- Inner lines: minimal or none

### Corners
- Slight rounding using pixel steps
- Avoid perfect squares unless intentional

### Detail Level
- Max 3–4 layers of detail
- Avoid noise

---

# 🎨 4. Color Rules

### Palette Structure
- Primary colors (brand-driven)
- Neutral colors (UI clarity)
- Accent colors (feedback)
- Status colors (success / warning / error)

### Rules
- Max ~6–10 colors per asset
- Use contrast for readability
- Avoid gradient unless controlled (2–3 steps max)

---

# 📓 5. Notebook Visual Rules

The notebook is the **main object of the simulation**.

### Must communicate:
- product quality
- positioning (cheap vs premium)
- customization

### Structure:
- cover
- binding
- pages thickness
- shadow base

### Variations:
- size (small / medium / large)
- material (basic / premium)
- condition (normal / upgraded)

---

# 👧 6. Mascot Rules

Mascot = **guide + feedback layer**

### Style:
- pixel anime girl
- chibi proportions
- expressive face

### Roles:
- guide user
- react to decisions
- show feedback

### Behavior:
- idle (neutral)
- happy (good result)
- concerned (warning)
- excited (success)
- thinking (decision phase)

👉 Must feel:
- friendly
- smart
- supportive (not annoying)

---

# 🖥 7. UI System Rules

### Components:
- buttons
- tabs
- panels
- slots
- cards

### States:
- default
- hover
- selected
- disabled
- active

### Rules:
- clear hierarchy
- readable labels
- strong contrast

---

# 🔘 8. Icon Rules

Icons represent:
- metrics
- actions
- categories

### Style:
- simple silhouette
- readable at small size
- consistent thickness

### Avoid:
- over-detail
- inconsistent shapes

---

# 💡 9. Lighting & Shading

### Light Source:
- top-left

### Shadows:
- bottom-right
- soft pixel shadow (1–2 tones)

### Highlights:
- subtle
- avoid over-glow

---

# 🔁 10. States System

Every asset must support states:

- default
- hover
- selected
- disabled
- premium
- warning

👉 States must be visible WITHOUT text.

---

# 🌍 11. Environment Rules

Environment = **context layer**

### Types:
- desk (single notebook view)
- shelf (multi notebook view)
- studio (production view)

### Rules:
- minimal clutter
- soft background
- not competing with UI

---

# ⚠️ 12. Common Mistakes (DO NOT)

- Mixing pixel styles
- Using too many colors
- Over-detailing small assets
- Inconsistent scale
- Unclear states
- Decorative-only visuals
- Breaking UI readability

---

# ✅ 13. Quality Standard

Before approving any asset, check:

1. Can user understand it in <1 second?
2. Does it follow pixel rules?
3. Does it match palette?
4. Does it match scale?
5. Does it support the system?

If NOT → reject.

---

# 🚀 Final Principle

👉 Every visual must answer:

**“What decision or outcome does this represent?”**

If it doesn’t → it should not exist.
