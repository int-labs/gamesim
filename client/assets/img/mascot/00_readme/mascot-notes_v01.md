# Mascot Notes v01

## Name
Final name not locked yet.

## Role
The mascot is the simulation’s guide, helper, and feedback companion.

It is not just decoration.  
It exists to:
- guide the user through the simulation
- react to decisions and outcomes
- make the experience feel alive
- reduce friction when explaining results, warnings, and insights

## Character Direction
The mascot is a:
- pixel anime girl
- chibi proportion
- soft, friendly, readable silhouette
- clean and consistent with the approved master style

This mascot should feel:
- smart
- warm
- supportive
- slightly playful
- not childish
- not noisy
- not overly dramatic

## Personality
The mascot should come across as:
- observant
- encouraging
- practical
- curious
- expressive but controlled
- helpful without being annoying

Think:
- studio assistant
- simulation guide
- business-learning companion

## Main Function in the Simulation
The mascot supports the user in key moments:

### 1. Tutorial / onboarding
- introduces the simulation
- explains what the player is doing
- explains what to pay attention to

### 2. Decision phase
- reacts while the player is selecting options
- helps frame choices
- supports thinking and comparison

### 3. Feedback phase
- reacts to good / bad / mixed outcomes
- helps users understand what changed
- makes the feedback more human and readable

### 4. Debrief phase
- summarizes the round
- reinforces the learning point
- supports reflection

## Tone of Voice
The mascot should sound:
- clear
- short
- warm
- confident
- helpful

Avoid:
- being too childish
- being too corporate
- sounding like a robot
- using too much text

## Visual Rules

### Art Style
- true pixel art only
- same outline logic as master style
- same palette family as approved direction
- same lighting and shading system as approved direction
- same scale logic as notebook and UI system

### Character Style
- anime-inspired face
- simplified readable eyes
- soft expression changes
- strong silhouette
- clear hair shape
- outfit should stay consistent

### Readability
The mascot must still read clearly at small sizes:
- 32px
- 48px
- 64px

Do not over-detail facial features or clothing.

## Proportion Rules
- head is larger than body in chibi style
- face should remain the most expressive area
- arms and hands should be simplified
- legs and feet should be compact and readable
- accessories should not overpower the character

## Expression Rules
Expression changes should be driven mainly by:
- eyes
- eyebrows
- mouth
- slight head tilt

Do not redesign the character per expression.  
Only the expression should change.

## Core Expression Set
These are the most important expressions:
- neutral
- happy
- excited
- thinking
- concerned
- warning
- confused
- proud
- celebrating
- sad

## Pose Rules
Poses should support simulation use cases:
- idle
- pointing
- presenting
- explaining
- analyzing
- cheering
- holding notebook
- holding pen
- sitting

Poses must remain readable and not too dynamic or complicated.

## UI Usage Rules
The mascot will appear in several forms:
- full body
- portrait
- bust
- icon head
- helper in corner
- speech bubble companion
- results panel companion

Each version must still look like the same character.

## Accessory Rules
Allowed accessories:
- notebook
- pen
- pointer stick
- magnifier
- badge items

Accessories are support props only.  
They should never distract from the character.

## FX Rules
Allowed simple FX:
- sparkle
- question mark
- exclamation mark
- sweat drop
- heart
- idea bulb

FX should remain small, clean, and secondary.

## State Logic
The mascot should visually support these states:
- tutorial
- hint
- success
- warning
- error
- loading
- empty state
- result summary
- debrief

These states should feel like system support, not random emotion changes.

## Do
- keep proportions consistent
- keep expressions readable
- keep silhouette strong
- keep detail controlled
- keep same palette family
- keep same lighting direction
- keep the character supportive and useful

## Don’t
- do not redraw the character in a different style
- do not over-detail small assets
- do not use inconsistent shading
- do not make the mascot too childish
- do not make the mascot too decorative
- do not let props overpower the character

## Approval Standard
Before approving any mascot asset, check:

1. Does it still look like the same mascot?
2. Is it readable at small sizes?
3. Does it match the approved master style?
4. Is the expression clear in under 1 second?
5. Does it support a real simulation use case?

If not, reject and revise.

## Production Priority
Generate in this order:
1. base
2. expressions
3. poses
4. states
5. ui usage
6. accessories
7. fx
8. summary sheets

## Final Principle
The mascot is not just a character.

It is a communication layer for:
- decisions
- feedback
- learning
- reflection
